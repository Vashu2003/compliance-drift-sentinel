# examples/

Real artifacts produced by Compliance Drift Sentinel, so output quality can be judged without
running the code. Every file here was generated by the system and copied verbatim — none of it
is illustrative prose written by hand.

| Artifact | What it demonstrates |
| -------- | -------------------- |
| [`margin_haircut_impact.md`](./margin_haircut_impact.md) | The **deterministic impact report**. For both a drop and a retype of `collateral.haircut_pct`, the exact three downstream margin columns that break, each with the transform that makes it break and the hop count. This is the part that must be correct; no LLM is involved. |
| [`margin_haircut_explanation.md`](./margin_haircut_explanation.md) | The **agent's narration and drafted data contract** (Gemini), grounded strictly in the report above. It names only the columns the engine found — the LLM explains impact, it never decides it. |
| [`margin_haircut_writeback.md`](./margin_haircut_writeback.md) | The **write-back artifact, read back out of a live DataHub**: the tags applied to each affected column and the contract text written into its description. This is what the next engineer inherits when they open the dataset. |
| [`../data/narrations.json`](../data/narrations.json) | Gemini output for **all five built-in scenarios** — drop, rename, retype, and a no-impact case. Useful for judging consistency across change types, including that the no-impact case correctly raises no alarm. |

## Severity, and why the retype matters most

| Change | Severity | Why |
| ------ | -------- | --- |
| `dropped` / `renamed` | `hard_break` | The transform loses an input and fails loudly. Easy to catch. |
| `retyped` | `silent_break` | The value still flows but miscomputes. **No error is ever raised** — a regulatory report just ships wrong numbers. This is the failure mode the project exists to catch. |
